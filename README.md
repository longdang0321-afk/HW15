# 과제 15: 퀵 정렬과 AVL 트리 정렬의 성능 비교

동일한 무작위 정수 데이터를 <strong>퀵 정렬(배열)</strong>과 AVL 트리로 각각 정렬한 뒤, 삽입·삭제를 반복하며 총 수행시간, 비교 횟수, 데이터 이동 횟수 및 최대 메모리 추정량을 비교합니다.

## 1. 프로젝트 구성 및 실행

| 파일 | 역할 |
|---|---|
| `main.c` | 데이터·연산 생성, 30회 반복 측정, 결과 검증 및 출력 |

## 2. 실험 조건

| 항목 | 설정 |
|---|---|
| 최초 데이터 수 n | 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000 |
| 삽입·삭제 연산 수 m | 최초 n의 20%, 즉 n / 5 |
| 초기 데이터 생성 | 각 크기에서 `srand(2026u)`, `rand() % 100000` |
| 연산 생성용 seed | 각 크기에서 `srand(12026u)` |

| 삽입·삭제 값 | 다음 난수로 별도 생성: `rand() % 100000` |
| 퀵 정렬 | 첫 원소 피벗, Lomuto 분할, 오름차순 |
| 중복 처리 | 배열은 각각 저장, AVL은 노드의 `count`에 중복 횟수 저장 |
| 삭제 | 해당 값 한 개만 제거하며, 없으면 다음 연산으로 진행 |
| 반복 측정 | 동일한 입력과 연산으로 매번 새로 시작하여 30회 실행 |
| 실행 순서 | 반복마다 두 방법의 실행 순서를 번갈아 변경 |
| 시간 측정 | `clock()`으로 측정한 CPU 시간의 평균(ms) |
| 메모리 산정에 사용된 크기 | int 4바이트, 포인터 8바이트, AVL 노드 32바이트 |

난수 데이터와 연산 배열을 측정 전에 생성하여 두 방법에 동일하게 전달합니다. 시간은 30회 평균이며, 비교·이동·메모리는 한 번의 전체 과정에 대한 값입니다.

같은 seed라도 C 라이브러리에 따라 난수열은 달라질 수 있습니다. 또한 `rand() % 100000`의 결과는 0~99,999 안에 있지만, 실제 생성 가능한 범위는 `RAND_MAX`에도 제한됩니다. 예를 들어 `RAND_MAX=32767`인 환경에서는 0~32,767만 생성됩니다.

## 3. 구현과 측정 기준

### 정렬과 데이터 조작

#### 배열

퀵 정렬 후 배열에서 위치를 선형 탐색합니다. 삽입은 뒤의 원소를 한 칸씩 밀고, 삭제는 뒤의 원소를 앞으로 당깁니다. 삭제 탐색은 해당 값보다 큰 원소를 만나면 중단합니다.

처음에는 n칸만 확보하고, 삽입 시 배열이 가득 차 있으면 m칸을 추가로 확보합니다. 새 배열로 기존 원소를 복사한 뒤 이전 배열을 해제합니다. 용량이 n+m이면 모든 연산에 충분하므로 확장은 최대 한 번만 발생합니다.

확장 복사는 이동 횟수와 시간에 포함하며, 확장 순간에는 두 배열의 메모리를 함께 계산합니다. 삭제 후에는 배열을 축소하지 않고 기존 공간을 재사용합니다.

#### AVL

노드에 중복 횟수를 저장하며, 삽입·삭제 후 재귀 호출이 돌아오면서 높이를 갱신하고 불균형한 노드를 회전합니다.

자식이 둘인 노드를 삭제할 때는 중위 후계자의 키와 중복 횟수를 함께 옮긴 뒤 `remove_min()`으로 후계자 노드 전체를 제거합니다. 후계자의 중복 일부가 두 노드에 남지 않도록 처리하며, 전체 원소 수는 한 개만 감소합니다.

최초 중위 순회에서는 중복 횟수만큼 정렬 결과 배열에 저장합니다. 이후 삽입·삭제도 같은 AVL 트리에서 직접 수행합니다.

### 총 수행시간

정렬 구간과 삽입·삭제 구간의 CPU 시간을 합하여 30회 평균(ms)을 출력합니다.

| 포함 | 제외 |
|---|---|
| 퀵 정렬 | 난수 생성 |
| AVL 노드 할당을 포함한 트리 구축 | 배열의 초기 준비 및 원본 복사 |
| 최초 AVL 중위 순회 결과 저장 | 정렬 결과 및 최종 결과 검증 |
| 배열 확장을 포함한 삽입·삭제 | 결과 출력 및 최종 자료구조 해제 |

중간 검증 시간을 제외하기 위해 정렬 구간과 삽입·삭제 구간을 나누어 측정한 뒤 합산합니다.

### 비교 횟수

데이터 값에 대한 `<`, `<=`, `==`의 실제 평가 한 번을 1회로 셉니다.

- AVL 탐색은 `==` 확인 후 필요한 경우 `<`를 확인하므로 노드 하나에서 최대 2회 발생합니다.
- 배열은 `<`로 위치를 찾고, 삭제 시에는 `==`로 존재 여부를 확인합니다.
- 실패한 삭제의 탐색도 포함합니다.
- 높이, 균형 인수, 인덱스, NULL, 중복 횟수 등 제어·메타데이터 비교와 검증용 비교는 제외합니다.

### 데이터 이동 횟수

명시적으로 수행되는 정수 키 값의 복사·대입 한 번을 1회로 셉니다.

| 동작 | 횟수 |
|---|---|
| 서로 다른 위치의 swap | 임시 변수 복사를 포함하여 3회 |
| 같은 위치의 swap | 생략 |
| 피벗 변수에 키 복사 | 1회 |
| 배열 원소 한 칸 이동 / 새 값 저장 | 각각 1회 |
| 배열 확장 시 기존 원소 복사 | 원소마다 1회 |
| AVL 새 노드의 키 저장 / 삭제 시 후계자 키 복사 | 각각 1회 |
| 최초 AVL 중위 순회 결과 배열에 저장 | 중복을 포함하여 n회 |

포인터 연결 변경과 회전, 높이·`count` 갱신, 함수 인자 전달, 준비·검증용 복사는 제외합니다. 따라서 AVL의 이동 횟수가 적다고 회전이나 탐색의 실행 비용까지 0이라는 뜻은 아닙니다.

### 최대 메모리 추정량

매 시점에 다음 식을 계산하여 최대값을 기록합니다.

```text
sizeof(Context) + sizeof(SortStats)
+ 현재 할당한 heap
+ 재귀 깊이 × FRAME_BYTES
+ 임시 배열
```

`FRAME_BYTES`는 다음과 같이 설정합니다.

```c
#define FRAME_BYTES (3 * sizeof(void *) + 4 * sizeof(int))
```

이는 재귀 호출의 보조 공간을 계산하기 위한 공통 추정 기준이며, 이 환경에서는 40바이트입니다. 두 방법에 같은 기준을 적용하지만, 실제 함수별 호출 프레임 크기가 같다는 의미는 아닙니다.

| 항목 | 계산 방법 |
|---|---|
| 배열 | 할당된 용량 전체. 확장 중에는 기존 배열과 새 배열을 함께 포함 |
| AVL | 살아 있는 노드 수 × `sizeof(Node)` |
| 최초 중위 순회 결과 배열 | 존재하는 동안 `n × sizeof(int)` 포함 |
| 재귀 보조 공간 | 현재 재귀 깊이 × `FRAME_BYTES` |
| 측정 구조체 | `sizeof(Context) + sizeof(SortStats)` |

이 환경에서 `sizeof(Context)=16`, `sizeof(SortStats)=64`, `sizeof(Node)=32`이며, 구조체 패딩도 포함됩니다.

heap은 요청한 바이트 수를 계산하지만 실제 호출 스택은 컴파일러에 따라 달라지므로 메모리 결과에는 추정이 포함됩니다. 프로세스 전체의 정확한 최대 메모리나 상한을 측정한 값은 아닙니다.

공통 원본·연산 배열, 최종 검증용 배열·빈도표, malloc 관리 정보 및 C 런타임은 제외합니다.

### 결과 검증

- 최초 정렬 결과가 오름차순인지 확인합니다.
- 최종 결과를 독립적인 빈도표와 비교하여 모든 값과 중복 횟수를 확인합니다.
- 두 방법의 최종 원소 수와 성공한 삽입·삭제 수를 비교합니다.
- AVL의 BST 순서, 양의 `count`, 저장 높이 및 모든 노드의 균형을 검사합니다.

## 5. 비교 및 분석

### 수행시간과 비교 횟수

이번 실행에서는 모든 n에서 AVL이 더 빨랐습니다. 시간 차이는 n=1,000에서 약 1.75배, n=20,000에서 약 17.5배였습니다. 다만 짧은 실행시간은 타이머 해상도와 실행 환경의 영향을 받으므로 작은 n의 차이를 과도하게 해석하지 않습니다.

배열은 연속된 메모리에 접근하지만 AVL은 노드 할당, 포인터 접근, 높이 갱신 및 회전을 수행합니다. 따라서 비교 횟수가 적다는 이유만으로 항상 시간이 짧아지는 것은 아닙니다.

n=20,000의 총 비교는 배열 41,237,170회, AVL 608,092회로 약 67.8배 차이가 났습니다. 최초 정렬 비교는 배열 339,846회, AVL 500,034회로 AVL이 더 많았습니다. 그러나 삽입·삭제 비교는 각각 40,897,324회와 108,058회였습니다.

즉 전체 차이의 주된 원인은 최초 정렬보다 이후 삽입·삭제 위치를 찾는 탐색입니다. 정렬 배열이라도 선형 탐색하면 연산마다 O(n)이 들지만, AVL은 균형을 유지하여 O(log n) 경로를 탐색합니다.

### 삽입·삭제의 데이터 이동

n=20,000의 삽입·삭제 단계에서 배열 이동은 30,053,508회, AVL은 1,312회였습니다.

배열 중간에 삽입하거나 삭제하면 뒤의 원소를 연속해서 옮겨야 합니다. 이번 구현에서는 확장 시 기존 20,000개 원소를 복사하는 비용도 포함됩니다.

AVL은 배열처럼 뒤의 모든 키를 이동시키지 않습니다. 새 노드 생성과 자식이 둘인 노드의 삭제에서는 키 저장·복사가 발생하지만, 회전은 주로 링크 변경으로 처리하고 중복 삽입은 `count`만 증가시킵니다.

전체 이동 횟수는 배열 30,544,120회, AVL 36,230회로 약 843배 차이가 났습니다. 다만 회전의 포인터 변경은 이동 횟수에서 제외되므로 이 비율이 총 작업량이나 실행시간의 비율을 뜻하지는 않습니다. 실제 시간 차이는 약 17.5배로 이동 횟수 차이보다 작았습니다.

### 메모리 차이

n=20,000에서 배열은 176,080바이트, AVL은 558,136바이트로 추정되어 AVL이 약 3.17배 컸습니다.

배열의 최대값은 확장 순간에 발생했습니다. 기존 n칸과 새 n+m칸이 함께 존재하므로 다음과 같습니다.

```text
기존 배열 + 새 배열 + 측정 구조체
= 20,000 × 4 + 24,000 × 4 + 80
= 176,080 Bytes
```

AVL의 최대값은 최초 중위 순회에서 발생했습니다. 최초 데이터의 서로 다른 값은 14,918개이며, 이때 메모리 계산에 사용된 재귀 깊이는 17입니다.

```text
노드 + 정렬 결과 배열 + 재귀 보조 공간 추정 + 측정 구조체
= 14,918 × 32 + 20,000 × 4 + 17 × 40 + 80
= 558,136 Bytes
```

AVL은 중복을 한 노드에 모아 노드 수를 줄이지만, 노드 하나에 키 외에도 `count`, `height`, 두 포인터와 패딩이 필요합니다. 따라서 이번 실험에서도 배열보다 큰 공간을 사용했습니다. 두 방법 모두 이 실험 범위에서는 O(n) 규모의 공간을 사용합니다.

### 데이터 크기 증가

n이 1,000에서 20,000으로 20배 증가할 때 배열의 총 비교는 약 360.6배, AVL은 약 28.5배로 증가했습니다. 시간은 배열이 약 320.5배, AVL이 약 32.1배 증가했습니다. 시간 증가율은 특히 작은 n의 측정 오차에 영향을 받을 수 있으므로 비교 횟수와 함께 해석합니다.

이번 실험에서는 연산 수도 m=0.2n으로 증가합니다. 배열 조작은 연산마다 선형 탐색과 원소 이동이 필요하므로 전체적으로 O(mn)=O(n²)입니다. 반면 AVL은 구축과 조작을 합하여 O((n+m)log n)입니다.

최초 퀵 정렬은 무작위 입력에서 평균 O(n log n)이지만, 첫 원소 피벗을 사용하므로 정렬된 입력이나 모든 값이 같은 입력에서는 O(n²)이 될 수 있습니다.

메모리 추정량은 배열이 약 19.8배, AVL이 약 15.5배 증가했습니다. 배열 용량은 n에 비례하지만 AVL 노드 수는 서로 다른 값의 수에 따라 결정됩니다. 값의 범위가 고정된 상태에서 중복이 증가하면 AVL 노드 수의 증가 비율은 전체 원소 수보다 낮아질 수 있습니다.

### 연산 분포의 영향

삽입과 삭제 시도는 약 절반씩 선택되었지만 실제 삭제 성공률은 달랐습니다. n=1,000에서는 삭제 시도 99회 중 3회로 약 3.0%, n=20,000에서는 2,026회 중 931회로 약 46.0%가 성공했습니다.

값의 범위가 고정된 상태에서 원소 수가 증가하면 삭제하려는 값이 이미 존재할 가능성도 커집니다. 실패한 삭제도 탐색 비용은 발생하지만 데이터 이동은 없습니다. 따라서 연산 선택 비율과 실제 데이터 증가·감소 비율을 구분해야 합니다.

n=20,000의 최종 원소 수는 다음과 같이 확인됩니다.

```text
최초 원소 수 + 삽입 수 - 삭제 성공 수
= 20,000 + 1,974 - 931
= 21,043
```

### 결론

정렬 상태를 유지하면서 삽입·삭제가 반복되는 이번 환경에서는 AVL이 유리했습니다. 배열은 선형 탐색과 원소 이동을 반복하지만 AVL은 트리의 균형을 유지하면서 O(log n)에 탐색·삽입·삭제를 수행하기 때문입니다.

반면 변경이 적거나 메모리 사용량을 줄여야 하는 경우에는 배열의 간결한 저장 방식이 유리할 수 있습니다. 이 결과는 한 seed와 선형 탐색 배열에 대한 결과이므로, 이진 탐색을 사용하는 배열이나 다른 난수 범위·연산 비율까지 그대로 일반화할 수는 없습니다.
